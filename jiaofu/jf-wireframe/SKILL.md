# 页面线框（含组件）

从③IA+②PRD+①旅程画出页面线框和组件。核心流程：EC情绪曲线先行驱动设计侧重 → PW自包含(含交互标注与框架标注) → SV/MS/DDR并行 → GC组件往复抽取 → CSM状态矩阵。

本skill输出是⑥生成和⑦汇报的素材——PW的交互标注让线框独立可评审。

## 入口纪律

**先走 jf-router 意图分类**：
1. 用 `products/jf-router/SKILL.md` 判断用户意图落在高保真工作法哪一层
2. 若目标 skill ≠ 本 skill → 终止本 skill 流程，输出路由结果并直接按目标 skill 执行
3. 若目标 skill = 本 skill → 继续本 skill 流程

**意图不清或方案不清晰时**：
- 需求模糊、业务逻辑不清 → 调用 `grill-with-docs` 盘问梳理
- 问题太大、路径不明 → 调用 `wayfinder` 建图寻路
- 梳理清楚后回到本 skill，重新走 jf-router 分类

## 每块产出

- **EC**：情绪曲线图（旅程轴+情绪高低点），双重角色——驱动设计+进⑦汇报
- **PW**：逐页ASCII线框+区域ID+交互标注（导航去哪/字段约束/状态触发）+框架标注（全幅route页 / 弹窗modal+hostPageId）
- **SV**：每状态的关键区域差异定义（空/加载/错误/正常态，重点状态细画）
- **MS**：弹窗规格（主体+hostPageId+renderMode，与宿主并排绘制）——只细化 PW 已判定为弹窗的操作
- **DDR**：每页每状态的数据字段和示例值
- **GC**：全局公共组件（≥3页重复提取）+状态定义
- **CSM**：用户状态×组件状态笛卡尔积矩阵

## 纪律

- **PW交互标注三要素**：导航（去哪）/字段约束（限制）/状态触发（何时可见）
- **PW框架标注**：本页是全幅 route 页还是弹窗 modal（弹窗标 hostPageId）；子流程页在 PW 页头标注宿主页与激活入口（如「由 P12『新增』按钮激活」）
- **弹窗判定前移到 PW**：哪些操作用弹窗、哪些用全幅子流程页，在 PW 阶段定——MS 只做弹窗细化，不重新判定
- **Rule of Three**：≥3页重复才抽GC，防过早抽象
- **SV被EC驱动**：高情绪状态（空/错误态）细画

## 弹窗 vs 全幅子流程页判定（PW 阶段执行，类型由 IA 定）

> 判定分工：LT 的「框架类型」由 IA 的 NM 类型列定义，PW 不推翻；本条是执行细则——逐操作判断「弹窗还是全幅子流程页」，结果进 PW 框架标注，并与 IA 的 sub-flow 归属、NM 类型列对齐。

| 呈现框架 | 适用操作 | 特征 |
|---------|---------|------|
| **modal 弹窗** | 轻量确认 / 录入 / 选择 | 单次交互、信息量小、不打断当前页 |
| **route 全幅子流程页** | 表单复杂 / 需多步骤 / 需留痕 | 承载独立子流程，需整页空间或审计痕迹 |

**判定规则**（PW 逐操作过一遍，结果进 PW 框架标注，不得与 IA NM 类型列冲突）：

1. 操作是否单次交互（确认/选一项/填少量字段）？→ 弹窗
2. 是否表单复杂、多步骤（向导式）、需留痕（操作记录/审计）？→ 全幅子流程页
3. 拿不准时：该操作是否需要独立路由（可被直接访问/回退）？需要→全幅；仅宿主页上下文中出现→弹窗
4. 子流程页在 PW 页头标注：宿主页 + 激活入口（如「由 P12『新增』按钮激活」），与 IA PS 的 sub-flow 归属一致

**MS 边界**：MS 只做弹窗主体的细化（主体+hostPageId+renderMode，与宿主并排绘制），不重新判定「该不该用弹窗」。
