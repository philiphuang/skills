# 内评核对（FDE 内评检查单机械核对）

按《FDE需求管理工作法》§6.1 FDE 内评检查单做机械核对：逐项过、给证据位置、产核对表；**不产出通过/不通过结论**——结论由质量评审人（项目经理终审）签出。

## 输入件

送内评的需求件全套：

1. MRD（业务规则、状态机权威）
2. PRD（FR/AC/API/权限）
3. 测试用例（BDD 场景文件＋AC 映射矩阵）
4. Demo 产物链（页面＋视觉评审数据与结论）

缺件即停，报「输入件缺 X，无法核对」，不猜测、不用不全的件凑数。

## 核对项清单（七项，照 §6.1 照搬，不改判据、不增不减）

| # | 评审面 | 检查项 | 判据 |
| --- | --- | --- | --- |
| 1 | PRD 面 | AC 可测性 | 每条 AC 为完整 Given/When/Then，可构造测试 |
| 2 | PRD 面 | 状态机引用 | 状态机只引用 MRD，无自行修改/补充；与 MRD 零冲突 |
| 3 | PRD 面 | 权限矩阵 | 每页面×角色有明确授权结论，无空白格 |
| 4 | PRD 面 | 数据字典 | 字段类型/来源/约束齐备 |
| 5 | PRD 面 | 上游追溯 | front matter upstream 齐备且 commit 为最新；规则溯源表无断链 |
| 6 | 测试用例面 | AC 映射 | 每条 AC ≥1 个 BDD 场景（映射矩阵全满） |
| 7 | 测试用例面 | 场景覆盖 | 状态驱动页逐态拆分、异常流程（驳回类）全有场景；MRD 数值规则（额度/期限类）均有边界场景 |

## 输出核对表格式

一行一检查项，逐项给结果与证据：

```markdown
# 内评核对表（<需求件名>，核对日期 <YYYY-MM-DD>）

| # | 检查项 | 核对结果 | 证据位置 | 备注 |
| --- | --- | --- | --- | --- |
| 1 | AC 可测性 | 过 / 不过 / 无法核对 | <PRD 文件>§<节> | <不过时：哪条 AC、缺什么> |
| ... | ... | ... | ... | ... |

本表为机械核对结果，通过/不通过结论由质量评审人（项目经理终审）签出。
```

- 「无法核对」必须注明缺什么（如「PRD 无权限矩阵节」）。
- 「不过」必须落到具体条目（如「AC-07 缺 Then 子句」），不写笼统评语。

## 红线（写死，任何情况下不越过）

1. **不产出结论**：不输出任何通过/不通过字样；核对表表尾固定话术原样保留。
2. **不改件**：不修改任何需求件内容、front matter、映射矩阵——核对只读。
3. **七项照搬**：不增项、不减项、不改判据；发现检查单外的问题，记入备注行，不入核对结果。
4. **不猜测**：证据位置必须是实际读到的位置；没读到就是「无法核对」，不推断「应该有」。
