# 原型渲染

**先读 manifest，再渲染**。输入是 `jf-ia` 产出的 `manifest.json`——页面清单、
导航与框架、跳转关系、状态、标注全在里面（契约见 `jf-contract`）。本步只做
一件事：把 manifest 变成**能点通的多页 HTML**。

不从 PRD 或线框倒推页面集合：页面该不该存在、属于哪个模块、standalone 还是
sub-flow、route 还是 modal，都是 IA（`jf-ia`）定下写进 manifest 的。渲染不增页、不减页。

```
1. 读 manifest.json（唯一真相源）
    ↓
2. 选执行者 —— 配了哪个外部执行者就用它（它成为这一步的**前置要求**，失败即硬失败）；一个都没配才走内置渲染器
    ↓
3. 渲染 —— 按 pages[].file 逐页落盘
    ↓
4. 过门禁 —— jf-validate --strict + 链接可达性检查；不过就打回重做
    （客户演示档 `--demo` 是另一棵树，门禁口径见「演示档过哪道门禁」）
```

**执行者只决定「谁写 HTML」，不决定「HTML 长什么样」**：导航树、页面框架、
从属与跳转、跳转协议、标注气泡协议都由 manifest 与本文件的渲染规则定死。
外部产出与内置产出过同一套门禁，一视同仁。

## 入口纪律

**正常路径**：由 `jf-prd` 在第 7 步调用。
**独立路径**：用户显式指名时可直接调用——此时先走 `jf-router` 判跨拍。

**manifest 不存在时**：本 skill 不自行推导页面集合——回 `jf-ia` 先出 manifest
（② 第 3 步），或先跑 `jf-validate` 看缺哪些字段。

**意图不清或方案不清晰时**：
- 需求模糊、业务逻辑不清 → 调用 `grill-with-docs` 盘问梳理
- 问题太大、路径不明 → 调用 `wayfinder` 建图寻路
- 梳理清楚后回到本 skill，重新走 jf-router 分类

## 渲染规则（所有执行者共同遵守）

页面归属（导航页/子流程页）与呈现框架（全幅/弹窗）由 IA（`jf-ia`）写入 manifest，
渲染按此执行——导航树只列导航页，框架与从属关系在页面框架区与下部关系区呈现。

### 跳转协议

```html
<a href="./<id>.html" data-nav="<id>">查看详情</a>
```

**脱离渲染器直接打开 `.html` 也能跳**：跳转不许依赖 JS 或任何工具链。
modal 在宿主页渲染为浮层（JS 未加载时退化为整页跳转）。

### 导航树只渲染「导航页」

- **侧边栏只列导航页**（IA PS 的 standalone 页）：列表/详情/看板等独立页面
- **子流程页不进导航树**：不占层级，宿主页下也不挂「⤷」特殊条目（2026-08-19 二轮裁定）
- 从属页面从导航树移出后，在页面下部「从属与跳转」区列出（见下）

### 页面框架区（每页 meta/框架标注）

- 每页标注框架：**route 全幅页** or **modal 弹窗**（弹窗标宿主页）——内置渲染器
  已实现，落在每页 meta 行的「框架：全幅 route 页 / 弹窗 modal」
- **宿主页**显示「本页激活：⤷ 材料上传」等（标注本页可激活的子流程页）——**未实现**，
  宿主页目前只在页面下部的「从属与跳转」区列「激活子流程」
- **子流程页**meta 行精简：保留「框架：子流程页 ⤷ 由「宿主」激活 ｜ 宿主：XX」——**未实现**

### 页面框架总表

全站每页标注 全幅/弹窗+宿主，**一页一行，覆盖 PS 全部页面（导航页+子流程页）**，
评审时一眼看清哪些是全幅页、哪些是弹窗：

| 页面 | 框架 | 挂载/宿主 |
|------|------|-----------|
| P03 需求列表 | 全幅 route | — |
| P11 材料上传 | 子流程页 ⤷ 由「需求详情」激活 | 宿主 P12 需求详情 |

⚠️ **目标态，不是现状**：内置渲染器**不产出**这张总表（现状是每页各自标框架，
首页 `index.html` 只列导航页）。外部执行者可自行实现；评审要总表的话，
现在得自己去 `manifest.json` 数。

### 页面下部「从属与跳转」区

集中列全与当前页相关的所有页面与跳转方式，分四类（链接可点击）：

| 类别 | 内容 | 说明 |
|------|------|------|
| **激活子流程** | 本页（宿主）可激活的子流程页 | 可点击跳转 |
| **由谁激活** | 本页是子流程页时，标注并链接宿主页 | 子流程页专用 |
| **下钻 / 返回 / 相关** | NM 跳转表的 drill/back/rel 三类跳转 | 链接可点击 |
| **免登录外部链接页** | 作为「相关」类条目，标注链接来源与评审对象 | 外部链接评审用 |

### 状态呈现

每页带状态切换（`states`），覆盖 default/empty/loading/error 占位；业务态另有
`editing`/`warning`/`blocked`/`success` 四个（演示档的场景步骤用得上）——
评审时要能当场切给客户看，不是静态截图。

### 标注气泡（渲染侧）

manifest 的 `annotations` 渲染成**编号徽标 + 气泡浮层**，供 ③ 设计评审逐条过：

- 徽标插在 target 命中元素的**开标签之后**（挂元素外面等于挂错控件）
- 点徽标弹气泡（title + content + 状态 + target），Esc / 点遮罩关闭
- **关掉 JS 也要能读到标注全文**——气泡是 `display:none` 的浮层、唯一打开路径是 JS，
  所以页面下部另出一份 `<details class="jf-ann-all">` **静态全览**，收录**全部**标注的
  编号/标题/状态/正文。少了它，落点标注的正文就只活在脚本里
- 三支判定：target 已在页面正文里 → 挂上去；命中骨架锚点 → 挂上去；
  都不中 → 进「**评审标注 · 未落点**」区 + stderr WARN

第三支是**显式承认没落点**，不是错误：外部执行者未接入时骨架里本来就没有
「批量审批按钮」这类业务元素，造个假的当落点才是骗评审。骨架锚点命名：

| 元素 | 锚点值 |
|---|---|
| 状态切换按钮 | `state-<状态>` |
| 「从属与跳转」区每个链接 | `rel-<渲染所在页>-<链接目标页>`（先源后目标，两段都是 pageId） |
| modal 浮层 | `modal-<pageId>` |

权威版本（三态词表、气泡协议全文、F4 与 WARN 的分工）见
`products/jiaofu/jf-contract/references/manifest-schema.md#annotations`。

## 三条产出档位

前两档是**同一棵树**（设计评审用），第三档是**另一棵树**（客户演示用）——
同一份 manifest，两场会、两个产物。

| 档位 | 产物 | 怎么开 |
|------|------|--------|
| **低保真** | 可跳转、可切状态的 manifest 骨架页 | 默认：内置渲染器；或外部执行者的结构优先模式 |
| **准高保真** | 在骨架上补真实文案 / 演示数据 / 完整视觉 | 外部执行者（生成式）：每页自包含元提示词，两步生成 |
| **客户演示版** | 上述任一 **+ `console.html`**，且每页**关掉 PM chrome**、**不产出三张 PM 展示页** | `--demo`（内置渲染器） |

准高保真是核心——元提示词自包含该页所需全部信息，两步产出（结构+视觉 → 文案+数据）。

**客户演示版不是「第三档质量」，是「第二个受众」**：设计评审是逐条过标注，
客户演示是按业务场景串场。把两者塞进一棵树，就是产品视角入侵用户视角。
**这两棵树的差别有三件事**：每页摘掉 PM chrome、**不产出三张 PM 展示页**、
多一张 `console.html`。第三件容易被忘——`index.html` / `components.html` /
`states.html` 写着「原型索引」「只列导航页（standalone）」「设计基线」、逐个列
页 ID 和组件×状态矩阵，全是工程视角；它们不在页面上，**在目录里**，客户双击
就打开。所以是**不产出**，不是留着不链。

## 演示控制台（console.html）

`--demo` 额外产出 `prototypes/console.html`——**客户演示的入口页**。
`index.html` 是 PM 的索引（只列导航页），`console.html` 是演示的串场表：
**模块 → 场景 → 步骤**，每条步骤链到目标页、非 default 步带 `?state=`。

```bash
# 客户演示档：另出一棵树；设计评审那棵照旧用不带 --demo 的命令出
# ⚠️ design 块按 root 解析——渲染进空目录会**静默**退回内置 tokens
#    （丢掉产品自己的视觉基线），所以要么在项目目录里渲染，要么连同
#    DESIGN.md / tokens.css 一起拷进目标目录
python3 products/jiaofu/jf-uxprompt/scripts/render_manifest.py <项目>/manifest.json --demo
```

场景来自 `manifest.scenes[]`（契约见 `jf-contract/references/manifest-schema.md#scenes`）：
每条场景声明 `moduleId` / `title` / `source` / 可选 `flow`，步骤是 `{pageId, state, label}`。
**manifest 没有 `scenes[]` 时**：console 退化为「模块 → 页面清单」（加强版索引）
并向 stderr 报 WARN——与套件「没配执行者就走内置路径」的既有约定一致，不是错误。

### `?state=` 传参约定

```html
<a href="./score-form.html?state=warning" data-nav="score-form">基础积分达上限</a>
```

- **仍是原生相对 href**，脱离任何工具都能跳——跳转协议的底线不为演示档让步；
- 页内脚本（`shared/components.js`）加载后读 `location.search`，按
  `.jf-state-btn[data-state="<状态>"]` 找到对应按钮并 `click()`——复用现成的切换
  路径，不是另改一套 DOM；
- **脚本未加载时页面停在 `default`**：退化方向与「modal 未加载时退化为整页跳转」
  一致。演示现场脚本报错，最坏是「没切到那个状态」，不是打不开页面。

状态名取自 `manifest.pages[].states`，I12 保证场景步骤的 `state` 真的存在于目标页
——控制台不会链到一个该页根本没有的状态。

### 演示档过哪道门禁

**两道门禁管的树不是同一棵**，别混：

| 树 | 门禁 |
|---|---|
| 设计评审树（默认渲染） | `validate_manifest.py --strict`（I1–I12 + F1–F4）+ `jf_contract_check.py` |
| 客户演示树（`--demo`） | `jf_contract_check.py <项目>/manifest.json --root <演示目录>` + `check_demo_separation.py <演示目录>` |

演示树**过不了 `validate_manifest.py --strict`，而且这是对的**：F4 问的是
「manifest 声明的每条标注在页面上有没有落点」，而演示档按设计不渲染标注层——
拿 F4 量演示树是**问错了问题**，不是演示树不合格。

实测演示树在 validate 下**只差 F4 这一项**（I1–I12 / F1–F3 全绿）；e2e 把这条边界
钉死：演示树若因别的原因出错就判失败。**不给 `jf-validate` 加「关掉检查」的开关**
——门禁的松紧不该由被检对象的旗标决定。

「演示档纪律」的**前三条**由 `check_demo_separation.py` 机器检查（A1–A6）：零 PM 关键词
（**扫原始文本，含 HTML 注释**——藏注释正是纪律第 2 条禁止的那件事）、零标注层
残留、三张 PM 展示页不得与 `console.html` 同层、`console.html` 必须在、页 ID 不得
作为**可见文本**出现（ID 留在 `href` / `data-nav` 里是跳转协议，允许）。

## 演示档纪律

演示树是**给客户看的**，四条硬纪律（前三条的「不许有什么」机器检查，第四条的
「该怎么写」人看）：

1. **正文层零 PM 注释**：FR/AC/BR/SM/UC 编号、规则来源、字段约束来源、内部决策、
   页面 ID / 路由 / 布局类型这类工程标注，一律不进演示树。客户按 Ctrl+U 也不该看到
   「评审标注」「模块：X｜CRUD」。落到实现上就是 `--demo` 整层不渲染标注层与 meta 行。
   **进度尾注同样不印**——「（错误文案待补）」「空态文案需与业务方确认」「列表页骨架」
   是写给 PM 的「这里还没写完」，客户看到只会以为产品没做完；渲染器**删尾注、不另造
   文案**（编一句像真的话术比留白更假，说人话/可执行/一致归第 4 条人工过）。
   演示档连 `pages[].note` 也不出——契约把它定义为「评审要点、待确认」，是内部内容。
2. **不靠隐藏层或注释作弊**：不许用「模式开关 / 隐藏层 / HTML 注释」把 PM 注释留在
   演示树里——那只是把它藏起来，物理上还在同一个文件、客户手一翻就见。**摘掉 ≠ 藏起来**。
3. **场景必须有来源**：`scenes[].source` 指回 FR/AC/BR/SM/UC 编号或文档锚点，且
   `title` 是客户可读的业务语言（不含编号）。**无来源的界面内容不得入演示框架**——
   场景 ≠ 笛卡尔积，只演示业务上真实会发生的状态组合（I12 拦）。
4. **正文文案是给客户读的，不是给开发读的**——三条文案纪律（源自合并前的 jf-hifi
   `copy-and-states.md`——该 skill 未发布、已并入本套件，并入时逐条核对过）：
   - **说人话**：不用「校验不通过」「数据未回流」这类实现语，用「请检查以下项」；
   - **可执行**：错误提示要给出**怎么改**，不是只报错；
   - **一致**：同一场景在列表、弹窗、提示处用同一句话。

   ⚠️ **这三条门禁不查**，A1–A6 只管「不许出现 PM 词」、管不了「文案写得好不好」
   ——「说人话」判不了。归本 skill 内部评审的「文案完整」那一项人工过，③ 设计评审现场一眼可判。

分界线：**演示结构**（模块 / 场景 / 步骤 / 状态切换）在演示树里是允许的，那正是客户
评审要看的「业务流程 → 状态」；**PM 注释**（设计依据与决策）分到产物 B——③ 的 `jf-review`
产出的设计注释文档，受众是 PM/内部，不是客户。

## 执行者

### 内置渲染器（降级方案）

无外部执行者时，用内置渲染器从 `manifest.json` 直接出多页原型：

```bash
# 以下命令一律以**本仓（skills-factory）根目录**为 cwd——三条路径分属三个目录，
# 混着写会出现在同一次会话里前一条能跑、后一条 command not found。
# manifest.json 按实际项目替换（产物默认落在 manifest 同级的 prototypes/）。

# 渲染（按 manifest 的 pages[].file 落盘，同时生成 shared/tokens.css、
# shared/components.js 与 index.html）
python3 products/jiaofu/jf-uxprompt/scripts/render_manifest.py <项目>/manifest.json

# 渲染后严格校验（文件存在性 + 跳转链接一致性 + 标注锚点 + status 词表）
python3 products/jiaofu/jf-validate/scripts/validate_manifest.py <项目>/manifest.json --strict

# 链接可达性（脱离渲染器直接打开 .html 也能跳）
python3 tests/e2e/jf_contract_check.py <项目>/manifest.json

# 客户演示档 / 演示树的链接可达性（--root 指到演示目录；validate 不适用于这棵树，
# 见上面「演示档过哪道门禁」）
python3 products/jiaofu/jf-uxprompt/scripts/render_manifest.py <项目>/manifest.json --demo
python3 tests/e2e/jf_contract_check.py <项目>/manifest.json --root <演示目录>
```

渲染规则（与上面的渲染规则一致，此处是它的落地细节）：

- 侧边导航只列 `standalone` 页，按 module 分组；`sub-flow` 页不进导航树
- 每个跳转都是 `<a href="./<id>.html" data-nav="<id>">`
- `modal` 关系在宿主页渲染为浮层（JS 未加载时退化为整页跳转）
- 每页带状态切换，覆盖 default/empty/loading/error 占位 + 四个业务态
  （`editing`/`warning`/`blocked`/`success`）
- 页面下部渲染「从属与跳转」区，分四类：**激活子流程 / 由谁激活 /
  下钻·返回·相关 / 外部链接**（`type: external` 或目标 `kind: external`）
- `annotations` 按三支判定落点：命中就挂徽标 + 出气泡，落不了就进
  「评审标注 · 未落点」区并报 WARN。（未落点条目仍带锚点、徽标照挂，
  所以 F4 照样过——**F4 只判自洽，不为「真的落上了」背书**；
  见 jf-validate 的「F4 管到哪为止」）
- 视觉用内置简洁单色规范（`prototypes/shared/tokens.css`）：近白画布、
  近黑文字、发丝边框、小圆角、无渐变；强调色禁止 Tailwind 默认蓝紫。
  交互脚本共享 `prototypes/shared/components.js`，不逐页内联。
  外部 design-system 接入后由 `DESIGN.md` 覆盖
- **`--demo` 关掉每页的标注层与 meta 行**（不是隐藏，是不渲染），**且不产出
  `index.html` / `components.html` / `states.html` 三张 PM 展示页**，另出
  `console.html`；状态切换按钮、「从属与跳转」区、modal 浮层都保留
  ——它们是演示要当场用的，不属于 PM chrome

### 外部执行者（候选）

装了就交给它，产出照样逐条过门禁。三行摘要（细则、安装命令、门禁细节见
中央登记表 `jf-contract/references/external-skills.md`——本 skill 涉及 S5/S6/S7）：

| 候选 | 输入 | 期望产出 | 门禁 | 不装时 |
|---|---|---|---|---|
| `interaction-prd` runtime | `manifest.json`（适配层转写） | 可点击原型底座 + 客户标注气泡 | `validate_manifest.py --strict` + `jf_contract_check.py` | 内置渲染器顶 |
| `html-style-generator` | 元提示词（PC+PB + 写死 Token + CS/DD 引用） | 多页自包含 HTML | 同上 | 同上 |
| `cc-designer` | `DESIGN.md` + `manifest.json` + 演示数据 | 自带完整视觉的多页 HTML | 同上 | 同上 |

**降级不是自动的，是你选出来的**：一个候选都没装 → 走内置渲染器，链路照跑；
配了哪个，哪个就是这个外包点的**前置要求**——调用失败即**硬失败**，不降级、
也不悄悄改走内置。后一条由编排层管（步骤表看见失败就停下）：`--strict` 量的是
manifest 本身，它看不见你配没配执行者，所以这一条不归它判。

### 元提示词路径（生成式执行者的内部实现）

上面那条 `html-style-generator` 之类的生成式执行者，内部是这么干的：
**每页一份自包含元提示词**，两步生成。不是本 skill 的入口，是执行者的一种做法。

```
 Step 0: 准备元提示词（每页一份，自包含全部信息）
    ├─ 覆盖声明（PC）+ 禁止事项（PB）← PC+PB合称
    ├─ Token/视觉：从设计体系写死拷贝（生成时不依赖设计体系）
    ├─ 文案引用：引用CS块（营销文案，独立定义）
    ├─ 数据引用：引用DD（演示数据集）
    └─ 导航/状态指令
    ↓
 Step 1: 结构 + 视觉（长什么样）
    布局骨架 + Token着色(写死值) + 视觉细节(写死值)
    → 骨架产物
    ↓
 Step 2: 文案 + 数据（说什么/显示什么）
    营销文案注入(引用CS块) + 演示数据加载(引用DD)
    → 完整准高保真
    ↓
 本 skill 内部评审（视觉/文案/数据三项）
    ↓ 通过
 交给③设计评审
```

内容块：

- **TS Token Surface**：每页贴标签（Marketing/Admin），准高保真用
- **元提示词(PC+PB)**：每页一份，自包含。Token/视觉写死值，文案/数据引用独立块
- **DD 演示数据集**：每状态一份JSON，准高保真加载
- **LF 低保真产物**：从 manifest 直接产出，可跳转可切换状态
- **CS 营销文案**：独立定义每页营销文案（中英文），元提示词引用，③ 抽文案确认表
- **准高保真产物**：两步生成，内部评审通过才给③

## 纪律

- **manifest 是唯一真相源**：渲染只解释它，不改它、不补页；发现 manifest 有问题回 `jf-ia`
- **执行者不豁免门禁**：外部执行者的产出与内置产出过同一套校验，不过就打回重做
- **Token/视觉写死值**：从设计体系拷贝进元提示词，生成时不依赖设计体系
- **内部先评审**：视觉准确/文案完整/数据正确三项通过才给③
- **结构文案归线框（jf-wireframe）**：本 skill 产营销文案，③ 只确认营销文案
- **不假装落点**：标注落不到真实元素上就显式进「未落点」区 + 报 WARN
- **场景必须有来源**：演示档的场景是业务上真实会发生的组合，`scenes[].source`
  指回上游编号（I12 拦）；不是「每页 × 每状态」的遍历

## 项目适配

本 skill 通用，不绑特定项目。以下可按项目调整：

- **目录路径**：产物的存放位置由使用者项目结构决定（由 `manifest.pages[].file` 定）
- **执行外包**：本步骤的执行可由外部 skill 完成。jf-* 只管编排和门禁——只要产出过门禁，
  谁做的无所谓。未外包时本 skill 自行执行。候选与安装命令见中央登记表
  `jf-contract/references/external-skills.md`（本 skill 涉及 S5/S6/S7，含标注气泡由谁出、演示档两条路）
- **推荐默认**：输出格式和载体默认可改——见各块最佳形态说明
