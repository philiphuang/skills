# 页面架构

从②PRD的功能需求和验收标准推导页面骨架：先梳理业务对象层级(BO)，再推导需要哪些页面(PS)、每种布局类型(LT)、页面间怎么跳转(NM)、功能怎么组织(FA)。5个内容块串行推进，全agent推导+人确认。推导顺序：**领域 → 业务对象层级 → 页面**（页面是业务对象的投影）。页面归属与呈现框架由 IA 定义，`jf-uxprompt` 渲染按此执行。

本skill输出是线框（jf-wireframe）和③评审汇报的基础素材——NM 是线框 PW 交互标注的源头（单页投影）。

## 入口纪律

**正常路径**：由 `jf-prd` 在第 3 步调用。
**独立路径**：用户显式指名时可直接调用——此时先走 `jf-router` 判跨拍。

**意图不清或方案不清晰时**：
- 需求模糊、业务逻辑不清 → 调用 `grill-with-docs` 盘问梳理
- 问题太大、路径不明 → 调用 `wayfinder` 建图寻路
- 梳理清楚后回到本 skill，重新走 jf-router 分类

## 5块生成流程

```
② FR+AC
    ↓
BO 业务对象层级：从需求清单领域+①MRD的BEN推导业务对象层级
    五步法：领域映射→实体汇总→层级分图→流程主管理对象→页面映射
    聚合根三问：状态在谁身上流转/子对象挂谁下/删掉谁业务无法独立
    ↓
PS 页面结构：围绕业务对象推导需要哪些页面
    触发规则：FR涉及UI交互→需要页面；AC的Given/Then含"打开页面"→该页面
    每页标注导航归属（导航页standalone / 子流程页sub-flow+宿主页）+主管理对象+CRUD
    ★ 门禁：随 PS 表同步输出 manifest.json 的 modules[] + pages[]
    ↓
LT 布局方式+页面框架：分析PS页面共性→提取布局类型
    先定义布局再分配页面；布局类型有限集合（顶部导航+侧边菜单+主内容区…）
    每页明确框架：route全幅页 or modal弹窗（弹窗标hostPageId），与NM类型列一致
    ↓
NM 导航地图：基于PS+LT定义页面间跳转
    固定格式：源页面/源元素/类型(route/modal/tab/external)/目标/触发条件
    类型列=route的页→全幅；=modal的→弹窗挂宿主页内；新增从属关系标注
    节标题带对象CRUD主线：跳转主线=同一对象的CRUD链，跨对象仅驾驶舱下钻
    ★ 门禁：随 NM 表同步输出 manifest.json 的 relations[]，并跑 jf-validate
    ↓
FA 功能架构：从NM推导功能架构——三层视图（领域→业务对象→功能模块）+标注角色归属
```

## 每块产出

- **BO**：业务对象层级（领域映射+实体汇总+层级分图+流程主管理对象+CRUD矩阵）— IA 的第一块
- **PS**：页面清单（中文名/英文名/路由/HTML文件名），含每个页面承载的FR + **导航归属** + **主管理对象** + **CRUD** 字段 → **同步输出 `manifest.json` 的 `modules[]` + `pages[]`**
- **LT**：布局类型定义+每页分配哪种布局 + **页面框架**（route全幅页 / modal弹窗+hostPageId）→ 落 `pages[].frame`
- **NM**：导航地图表（全局，全站页面间跳转关系）+ 页面从属关系 + 节标题对象CRUD主线 — 是线框（jf-wireframe）PW 交互标注的源头 → **同步输出 `manifest.json` 的 `relations[]`**
- **FA**：功能架构图（领域→业务对象→功能模块三层视图+角色归属）— 原「子系统→模块」二层的按负责人罗列视图降为历史留存
- **manifest.json**：**本 skill 的机器可读产物**，是下游线框（jf-wireframe）/原型渲染（jf-uxprompt）的唯一输入。字段定义见 `products/jiaofu/jf-contract/references/manifest-schema.md`

## 产物契约：manifest.json（PS/NM 双门禁）

文档表给人看，**manifest 给机器看**。两块各有一道门禁，缺一不可。

### 门禁 1（PS 后）：modules[] + pages[]

PS 表定稿时，同一轮必须产出 manifest 的 `modules[]` 与 `pages[]`。
字段映射：

| jf-ia 来源 | manifest 字段 | 说明 |
|---|---|---|
| 领域/模块 | `modules[]` | `id` 用英文短名，`title` 中文名，`navNumber` 导航序号 |
| BO 第5步「主管理对象」 | `pages[].obj` | 同域页面共享聚合根 |
| PS「CRUD」列 | `pages[].crud` / `crudNote` | 含 `D` 必须写业务替代动作（停用/退回/覆盖导入） |
| PS「导航归属」列 | `pages[].nav` / `hostPageId` | `standalone` 不填宿主；`sub-flow` 必填 |
| PS「HTML 文件名」列 | `pages[].file` | **basename 必须等于 `pages[].id`** |
| PS「承载 FR」列 | `pages[].fr` | AC 有对应则填 `ac` |
| LT「页面框架」列 | `pages[].frame` | `route` / `modal`（modal 必填 hostPageId） |
| 页面类型（列表/详情/表单/看板/确认） | `pages[].kind` | `list`/`detail`/`form`/`dashboard`/`confirm`/`external` |
| 设计约定 | `pages[].device` / `viewport` | 默认 `desktop` + 1440×900，固定视口保证渲染可复现 |
| 状态约定 | `pages[].states` | 至少 `default`，建议补 `empty/loading/error` |

**判定顺序**：先定 `nav`（用户能不能不经操作直达）→ 再定 `frame`（NM 类型列）→ 两者不一致即缺陷。

### 门禁 2（NM 后）：relations[] + 校验

NM 表定稿时，同一轮必须产出 `relations[]`，并**跑通校验**：

```bash
python3 products/jiaofu/jf-validate/scripts/validate_manifest.py manifest.json
```

字段映射：

| NM 列 | manifest 字段 |
|---|---|
| 源页面 | `from` |
| 目标 | `to` |
| 类型（route/modal/tab/external） | `type`（`route` → 目标必须 `frame: route`；`modal` → 目标必须 `frame: modal` 且 `hostPageId == from`） |
| 源元素 | `label` / `trigger`（selector 形式，如 `[data-nav=demand-detail]`） |
| 触发条件 | `condition` |
| 节标题对象CRUD主线 | `semantic`：`drill`（下钻）/`back`（返回）/`activate`（激活子流程）/`rel`（相关） |

**校验不通过 = 本块未完成**，禁止进入 FA 与线框。常见打回原因：id 与文件名不符、
关系指向不存在页面、sub-flow 缺宿主页、modal 的宿主不是源页、crud 含 D 没写替代动作。

### 为什么必须双写

manifest 是**真相源**，文档表由它派生——两边冲突时以 manifest 为准。
只写文档表不写 manifest，下游每次生成都要把文档重新猜一遍，细节必然丢。

## 纪律

- **全串行**：BO→PS→LT→NM→FA，上游不就绪不下游
- **BO是源头**：BO 梳理业务对象层级，页面挂在对象下；同域页面共享聚合根，导航分组与对象层级一致
- **NM是源头**：NM定义全站跳转关系，线框 PW 消费NM做**单页投影**——NM是全局表，PW是抽取本页跳转的内联标注（导航去哪/字段约束/状态触发）。不重复定义
- **LT与NM一致**：LT的框架分配与NM的类型列必须一致——类型列=route的页→全幅页；=modal的→弹窗挂宿主页内。不一致评审即判为缺陷
- **从属关系双向可查**：子流程页行标宿主页（←宿主 XX），宿主页行标可激活的子流程页（→P11 子流程页），两处互相对得上
- **CRUD 默认口径**：业务系统无物理删除——D 一律写业务替代动作（停用/退回/覆盖导入）
- **agent推导+人确认**：五块都是mapping型，agent从源码推，人确认
- **manifest 同步输出**：PS 出 `modules[]+pages[]`、NM 出 `relations[]`，两次门禁都要跑 `jf-validate`；契约字段见 `products/jiaofu/jf-contract/references/manifest-schema.md`
- **manifest 是真相源**：与文档表冲突时以 manifest 为准，文档表由它派生

## BO 业务对象层级（第一块）

先对象后页面：领域 → 业务对象层级 → 页面。梳理清楚「流程管什么对象」比「流程有哪些页面」更本质——页面是对象的投影。

### BO 五步法

1. **领域映射**：按客户需求清单的一级模块领域（如 考核/项目/产学研/奖励/成果/综合/新质能力），把各模块 MRD 锚定到领域切片。模块 = 领域的首批落地，不是平行子系统；后续新功能按领域挂载
2. **实体汇总**：把全部 MRD 的 BEN 抽出来，标注层级（聚合根/子/孙/交叉/引用）与基数（1:1 / 1:N / 每X一条）。基数直接决定页面是列表还是详情、行主键怎么设计
3. **层级分图**：每域独立画对象层级图（不做全站总图），明确聚合根；识别特殊结构（见下）
4. **流程主管理对象**：每个业务流程一句话点名主管理对象，再围绕对象列 CRUD 矩阵（操作/入口页面/对应 FR）——「流程管什么对象」比「流程有哪些页面」更本质
5. **页面映射**：每页标注主管理对象 + CRUD 定位（进 PS 两列）

### 聚合根判定（每域三问）

1. **谁承载业务流程的推进**？——状态在谁身上流转（需求项目、提案、月度考核期……）
2. **谁的子对象生命周期随它创建/更新/消亡**？——材料版本、评审任务、归档结果都挂在根下
3. **删掉它，业务是否无法独立存在**？——能独立存在的都是根

### 特殊结构（纯罗列发现不了，第四步专查）

| 结构 | 特征 | 处理 |
|------|------|------|
| **双根域** | 两个正交聚合根（人轴 × 时间轴），交叉对象 = 双根的交（打分记录 = 员工 × 考核期） | 图内双根标注，交叉对象挂交点 |
| **平台级共享对象** | 一个实体被多个领域消费（专家：本期模块 3 用，v2 归综合管理） | 数据结构按平台级设计，页面可暂挂模块内 |
| **跨模块流转对象** | 同一实体的两端视图（积分年度汇总：模块 5 产出 → 模块 6 入库） | 两处 MRD 各声明，实为同一对象 |
| **同构对象** | 多个模块长得一样的实体（留痕记录四字段） | 统一组件/表设计 |
| **同名不同物** | 同名但业务含义不同（需求项目 ≠ 关联项目） | 文档与页面命名区分，防评审歧义 |

### 层级图按域分图

- **不做** 5 个 subgraph 挤一张总图
- **领域总览**（仅聚合根 + 跨域虚线）：跨域关系（积分年度汇总流转、专家共享、组织架构底数据）只用虚线表示
- **每域独立层级图**：图标题带聚合根标注（如「聚合根：**需求项目**」「双根域」）

### BO 待确认

- 单独列清，不埋在正文：领域锚点、共享对象升级、同名区分等
- 业务方拍板后方法论才生效（2026-08-21 用户拍板：四项待确认全部同意）

### 原型渲染侧引用（LF 呈现对象层级）

- LF 侧边栏导航分组与 BO 聚合根对齐（模块 = 领域切片，组内页面共享聚合根）
- 页面 meta 行加「主管理对象」：PAGES 每页新增 `obj` 字段（主管理对象＋CRUD 定位，取自 BO 第5步/PS CRUD 列），meta 行渲染为「对象：XX｜R（…）」插在路由前

## 页面归属与呈现框架

页面分两类归属、两种框架，由 IA 统一定义，`jf-uxprompt` 渲染按此执行，评审按此核对。

### 导航归属（PS 必标）

| 归属 | 说明 | 判定 | 出现在左侧导航 |
|------|------|------|---------------|
| **导航页 standalone** | 列表/详情/看板等独立页面 | 有独立导航入口，用户直接到达 | ✅ |
| **子流程页 sub-flow** | 由宿主页操作激活（「新增」「上传」「导出」按钮 → 子流程页） | 无独立导航入口，只能从宿主页进入 | ❌ 不在导航树，标注宿主页 |

**标注格式**（PS 页面清单新增「导航归属」+「主管理对象」「CRUD」三列）：

- 导航页：`standalone`
- 子流程页：`sub-flow ←宿主 P12`（如 `P11 子流程页 ← 宿主 P12`）

**主管理对象 + CRUD 列**（PS 必填，取自 BO 第5步）：

- 主管理对象：本页主要管理的业务对象（同域页面共享聚合根）
- CRUD：本页在对象生命周期中的定位（如 需求项目：R 列表 / C 登记 / U 复核；D 默认业务替代动作：停用/退回/覆盖导入）
- 导航分组与对象层级一致：组内页面共享聚合根

**导航归属判定**（防漏判）：

- 子流程页通常是「新增/编辑/上传/导出」的目标页——用户经宿主页操作进入，**不进左侧导航树**
- 导航页是「列表/详情/看板」——有独立导航入口，进左侧导航树
- 拿不准时：用户能不能不经任何操作直接到达该页？能→导航页；只能经宿主页操作到达→子流程页

**业务对象层级（BO 块）**：见上文「BO 业务对象层级」节——本块置于 IA 首位，PS/LT/NM 按对象层级组织，本节归属与框架定义不变。

### 页面框架（LT 必标，与 NM 类型列一致）

| 框架 | 判定（NM 类型列） | 挂载 | 形态 |
|------|------------------|------|------|
| **route 全幅页** | 类型列 = route | 独立路由 | 整页呈现 |
| **modal 弹窗** | 类型列 = modal | 挂在宿主页内（标 hostPageId） | 浮层呈现，不换页 |

**规则**：

- 每页在 LT 明确呈现框架：全幅 route 页 or modal 弹窗（弹窗标注 hostPageId）
- LT 布局分配与 NM 类型列**必须一致**：类型列=route 的页 → 全幅；=modal 的 → 弹窗挂在宿主页内（不一致评审即判为缺陷）
- modal 弹窗的宿主 = 哪个页面能打开它，标 `hostPageId`

### 从属关系（NM 必标，双向可查）

NM 每页新增「从属关系」标注，双向对齐：

- **子流程页行**：`←宿主 XX`（标注宿主页）
- **宿主页行**：`→P11 子流程页`（标注可激活的子流程页）

### 节标题 CRUD 主线（NM 必标）

每个模块节标题带对象 CRUD 主线——`对象：XX（C 登记 → R 列表 → U 复核…）`：

- 跳转主线 = 同一业务对象的 CRUD 链（创建→列表→详情→编辑/复核，沿对象生命周期串起来）
- 跨对象跳转仅驾驶舱下钻（其他一律不跳对象）

### 原型渲染规则（LF，评审对照）

- **侧边栏只列导航页**：子流程页彻底不进左侧导航，宿主页下不挂「⤷」特殊条目
- **页面下部「从属与跳转」区**：集中列全与当前页相关的所有页面与跳转方式，分四类：
  - **激活子流程**：本页（宿主）可激活的子流程页（可点击跳转）
  - **由谁激活**：本页是子流程页时，标注并链接宿主页
  - **下钻 / 返回 / 相关**：NM 跳转表的 drill/back/rel 三类跳转（链接可点击）
  - **免登录外部链接页**：作为「相关」类条目，标注链接来源与评审对象
- **meta 行精简**：子流程页保留「框架：子流程页 ⤷ 由「宿主」激活 ｜ 宿主：XX」；宿主页不再冗余显示激活列表（移到下部「从属与跳转」区）
- **meta 行插对象**：在 meta 行插入「对象：XX｜R（…）」（主管理对象＋CRUD 定位，取自 BO 第5步/PS CRUD 列）

## 产物自检（收尾必跑）

```bash
# 1. 校验契约（PS/NM 定稿后各跑一次）
python3 products/jiaofu/jf-validate/scripts/validate_manifest.py manifest.json

# 2. shaping 待确认回查（项目有 shaping/ 时必跑；无则跳过）
python3 products/jiaofu/jf-interview/scripts/check_shaping.py <shaping目录> --manifest manifest.json

# 3. 渲染出原型，确认每页可打开、跳转可点通
python3 products/jiaofu/jf-uxprompt/scripts/render_manifest.py manifest.json

# 4. 渲染后严格校验（含文件存在性与跳转链接一致性）
python3 products/jiaofu/jf-validate/scripts/validate_manifest.py manifest.json --strict
```

第 2 步是 G5 的 ERROR 档：`shaping/07-open-questions.md` 每条待确认的「影响页面」
必须落在 `manifest.pages[]` 里。jf-interview 首次跑门禁时 manifest 尚不存在、加不了
