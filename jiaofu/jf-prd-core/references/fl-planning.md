# FL 功能清单参考

> jf-prd-core 的技术参考——从产品愿景到功能清单的映射规则。在需要生成版本规划时加载。

## 生成规则

- **上游**：PV（产品愿景，含 success-metrics + 目标用户 + 核心价值）
- agent 推导 + 人确认

## 映射规则

1. 从 PV 定位 → 功能领域边界
2. 从 success-metrics → 功能优先级排序
3. 版本切分：MVP（覆盖 CP 主路径，自洽可独立演示）→ V1/V2…逐版扩充
4. **delta-description**：每版声明相对上版的增量变化（新增/修改/移除），依托功能 ID 追溯，非全量重写

## 每功能字段

| 字段 | 示例 |
|------|------|
| 功能ID | F001 |
| 名称 | "活动创建" |
| 描述 | "管理员创建营销活动" |
| 优先级 | P0（MVP） |
| 所属模块 | "活动管理" |
| 所属版本 | V1 |

## 门禁

- MVP 自洽（独立演示，覆盖 CP 主路径）
- 版本间增减可追溯到功能 ID
- delta-description 非全量重写

## FL 归谁

FL **不在 ① MRD 里**——MRD 只记录业务事实，FL 是版本规划动作，不是业务真相。

它由 **② 的 FR 网关**承担：从 ① 的 UC 映射 FR 时，按本文件的版本计划过滤，只产出本版本功能的 FR。本文件因此住在 `jf-prd-core/references/`。

若复杂度增长，可再独立成 `/feature-roadmap` skill。
