# 页面线框（含组件）

从③IA+②PRD+①旅程画出页面线框和组件。核心流程：EC情绪曲线先行驱动设计侧重 → PW自包含(含交互标注) → SV/MS/DDR并行 → GC组件往复抽取 → CSM状态矩阵。

本skill输出是⑥生成和⑦汇报的素材——PW的交互标注让线框独立可评审。

## 入口纪律

**先走 jf-router 意图分类**：
1. 用 `products/jf-router/SKILL.md` 判断用户意图落在高保真工作法哪一层
2. 若目标 skill ≠ 本 skill → 终止本 skill 流程，输出路由结果并直接按目标 skill 执行
3. 若目标 skill = 本 skill → 继续本 skill 流程

**意图不清或方案不清晰时**：
- 需求模糊、业务逻辑不清 → 调用 `grill-with-docs` 盘问梳理
- 问题太大、路径不明 → 调用 `wayfinder` 建图寻路
- 梳理清楚后回到本 skill，重新走 jf-router 分类

## 7块生成流程

```
①用户旅程(JF) + ③页面架构(PS+LT+NM) + ②PRD
    ↓
EC 情绪曲线：先于PW，驱动后续设计侧重
    驱动：页面优先级 / 状态设计重点 / 视觉文案重点
    ↓
PW 页面线框：ASCII线框 + 交互标注（导航/字段约束/状态触发）
    标注从③NM+IA单页投影，让PW独立可评审
    ↓
┌──────────┬──────────┬──────────┐
SV 状态变体  MS 弹窗规格  DDR 演示数据需求
(重点状态   (弹窗主体+  (每页每状态数据
细画,EC驱动) hostPageId)  字段+示例值)
└──────────┴──────────┴──────────┘
    ↓
GC 全局组件：从PW抽取（Rule of Three：≥3页重复才提取）
    组件与页面往复看，防过早抽象
    ↓
CSM 组件状态矩阵：GC × 用户状态笛卡尔积
```

## 每块产出

- **EC**：情绪曲线图（旅程轴+情绪高低点），双重角色——驱动设计+进⑦汇报
- **PW**：逐页ASCII线框+区域ID+交互标注（导航去哪/字段约束/状态触发）
- **SV**：每状态的关键区域差异定义（空/加载/错误/正常态，重点状态细画）
- **MS**：弹窗规格（主体+hostPageId+renderMode，与宿主并排绘制）
- **DDR**：每页每状态的数据字段和示例值
- **GC**：全局公共组件（≥3页重复提取）+状态定义
- **CSM**：用户状态×组件状态笛卡尔积矩阵

## 纪律

- **PW交互标注三要素**：导航（去哪）/字段约束（限制）/状态触发（何时可见）
- **Rule of Three**：≥3页重复才抽GC，防过早抽象
- **SV被EC驱动**：高情绪状态（空/错误态）细画
