# 页面架构

从②PRD的功能需求和验收标准推导页面骨架：需要哪些页面(PS)、每种布局类型(LT)、页面间怎么跳转(NM)、功能怎么组织(FA)。4个内容块串行推进，全agent推导+人确认。

本skill输出是⑤线框和⑦汇报的基础素材——NM是⑤PW交互标注的源头（单页投影）。

## 4块生成流程

```
② FR+AC
    ↓
PS 页面结构：从FR+AC推导需要哪些页面
    触发规则：FR涉及UI交互→需要页面；AC的Given/Then含"打开页面"→该页面
    ↓
LT 布局方式：分析PS页面共性→提取布局类型
    先定义布局再分配页面；布局类型有限集合（顶部导航+侧边菜单+主内容区…）
    ↓
NM 导航地图：基于PS+LT定义页面间跳转
    固定格式：源页面/源元素/类型(route/modal/tab/external)/目标/触发条件
    ↓
FA 功能架构：从NM推导子系统→功能模块层级+标注角色归属
```

## 每块产出

- **PS**：页面清单（中文名/英文名/路由/HTML文件名），含每个页面承载的FR
- **LT**：布局类型定义+每页分配哪种布局
- **NM**：导航地图表（全局，全站页面间跳转关系）— 是⑤PW交互标注的源头
- **FA**：功能架构图（子系统→功能模块层级+角色归属）

## 纪律

- **全串行**：PS→LT→NM→FA，上游不就绪不下游
- **NM是源头**：NM定义全站跳转关系，⑤PW消费NM做**单页投影**——NM是全局表，PW是抽取本页跳转的内联标注（导航去哪/字段约束/状态触发）。不重复定义
- **agent推导+人确认**：四块都是mapping型，agent从源码推，人确认


## 项目适配

本 skill 通用，不绑特定项目。以下可按项目调整：

- **目录路径**：产物的存放位置由使用者项目结构决定（推荐默认见各块说明）
- **执行者委派**：本 skill 的 [UX设计] 能力可委派给外部 skill。配置见 `.jf/config.yaml`（模板见 `products/jf-config.example.yaml`）。未配置时本 skill 自行执行
- **推荐默认**：输出格式和载体默认可改——见各块最佳形态说明
