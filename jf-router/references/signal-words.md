## 2. jf-* skill 能力边界与触发信号词

## 3. 边界模糊词归类建议

以下是容易跨层/跨 skill 的模糊词及其归类规则：

| 用户说的 | 可能指向 | 归类建议 | 仲裁策略 |
|----------|---------|---------|---------|
| **"需求"** | ① MRD（业务需求）<br>② PRD（功能需求） | 看上下文——如果讨论"做什么业务"→①；如果讨论"功能怎么验收"→② | 默认 ①（源头）：需求先落到业务建模，业务清楚了再谈功能 |
| **"设计"** | ② PRD（API设计）<br>③ IA（页面架构）<br>⑤ Wireframe（线框） | 看上下文——API/接口设计→②；页面结构/导航→③；线框/具体页面→⑤ | 默认 ③（IA）：设计=页面架构是高频意图 |
| **"页面"** | ③ IA（PS页面结构）<br>⑤ Wireframe（PW线框）<br>⑥ UXPrompt（生成） | 看阶段性——只问"有哪些页面"→③；画"页面具体怎么排"→⑤；"生成页面"→⑥ | 默认 ③：先搞清楚页面结构，再画/再生成 |
| **"数据"** | ① MRD（BEN实体）<br>④ Data（DC数据域/TFD表） | 看粒度——"有哪些实体"→①；"表怎么设计"→④ | 默认 ①（源头）：数据模型从业务实体来 |
| **"状态"** | ① MRD（SM状态机）<br>⑤ Wireframe（SV状态变体） | 看范畴——"有哪些状态/状态怎么流转"→①；"每种状态下页面怎么显示"→⑤ | 默认 ①（源头）：状态定义在MRD，线框只能引用 |
| **"权限"** | ② PRD（RP角色权限）<br>③ IA（PP页面权限） | 看对象——"谁能做什么操作"→②；"谁能访问什么页面"→③ | 默认 ②（源头）：先有能力再有页面权限 |
| **"生成/写代码"** | ⑥ UXPrompt（生成低保真）<br>4.0（高保真代码） | 看阶段——低保真验证→⑥；正式开发→4.0 | 看前置：无2.0产出→⑥；2.0全部完成且门禁通过→4.0 |
| **"测试"** | ⑧ jf-test（BDD+TC）<br>通用编码测试 | 看范畴——验收测试→jf-test；单元测试/集成测试→非jf-* | 看是否有AC：有AC→jf-test |
| **"评审/汇报"** | ⑦ jf-review（客户评审）<br>各层门禁 | 看对象——客户/老板看→jf-review；PM内部确认→层门禁 | 按对象区分 |
| **"组件"** | ⑤ Wireframe（GC全局组件）<br>4.0 FE（代码组件） | 看阶段——设计阶段→⑤；编码阶段→4.0 | 默认 ⑤（源头）：先设计组件规格再实现 |

## 4. 路由优先级规则

当用户表达同时命中多个 skill 的信号词时：

```
优先级: 层序号越小越优先（从源头开始）

jf-mrd (1.0) > jf-prd (2.0) > jf-ia (2.0) > jf-data (2.0)
> jf-wireframe (2.0) > jf-uxprompt (2.0) > jf-test (3.0) > 4.0（非 jf-*）

jf-review 特殊:
  有已有产出物 → 执行 jf-review
  没有 → 拒绝，指向源头
```

同层内 (2.0 有 5 个 skill) 的次级优先级:

```
jf-prd > jf-ia ≈ jf-data > jf-wireframe > jf-uxprompt
```
（jf-ia 和 jf-data 并行，同时命中时优先 jf-prd，因为 jf-prd 是 jf-ia 的上游）

## 5. DAG 依赖映射（路由层用）

路由层不需要追踪块是否就绪，但需要知道"哪个 skill 是哪个的源头"来判定路由方向：

```
用户说 → 信号词匹配 → 目标 skill

jf-mrd (源头，无上游)
  ├─→ jf-prd  (消费 MRD 的 UC+SM+BRO)
  ├─→ jf-data  (消费 MRD 的 CP+BEN, 绕开 PRD)
  └─→ jf-review (消费 MRD 各块)

jf-prd (消费 MRD)
  ├─→ jf-ia  (消费 PRD 的 FR+AC)
  ├─→ jf-wireframe  (消费 PRD+IA+JF)
  └─→ jf-test  (消费 PRD 的 AC)

jf-ia (消费 PRD)
  └─→ jf-wireframe  (IA 的 PS+LT+NM 是 PW 的前置)

jf-data (消费 MRD，与 IA 并行)
  └─→ (独立链，下游是 4.0 DB)

jf-wireframe (消费 IA+PRD+JF)
  └─→ jf-uxprompt  (PW+CSM+NM 是元提示词前置)

jf-uxprompt (消费 Wireframe+PRD+IA)
  └─→ jf-review (准高保真产物进评审)

jf-review (横切，消费一切 → 反馈回流 MRD)
  └─→ jf-mrd (反馈闭环)

jf-test (消费 PRD 的 AC + jf-review)
  └─→ (验收 4.0 代码)
```
