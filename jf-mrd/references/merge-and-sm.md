# 增量沉淀与 SM 聚合参考

> jf-mrd 的技术参考——增量合并、冲突裁决、SM 聚合。
> 在需要合并新规则、处理冲突、聚合状态机时加载。

## 增量合并

新已确认规则进入时，agent 按**实体+属性**维度与已有规则集比对：

| 结果 | 条件 | 处理 |
|------|------|------|
| **新增** | 没有同类约束 | 追加 |
| **细化** | 同类约束但互补 | 合并/更新 |
| **疑似冲突** | 同类约束且矛盾 | 标记，进人工裁决 |

比对维度：按标签体系的实体+预定义主分类定位同类约束。

## 冲突检测与裁决

- **agent 自动标疑似冲突**：只标不裁——不做业务判断
- **全人工裁决**：业务规则需人判断
- **来源仅作裁决参考**（章程 > 会议口述 > 竞品推断），不自动优先级
- **裁决结果回流**：采新→旧[被修订]；保留旧→新[废止]或合并

## SM 聚合视图

SM 不是独立产物——是**加工层 Given/When/Then 决策单元中"涉及状态变更"子集的聚合视图**：

```
加工层全部决策单元
    ↓ 筛选：Then 含"状态变为/状态置为"
    ↓ 聚合：状态=节点，转换条件(When)=边
SM 状态转换图
```

SM 字段：状态定义(Then) / 金额([金额]类BR) / 权限([权限]类BR) / 转换条件(When)

**聚合示例**：
```
BR-07: When 金额>5000 Then 状态→"待审核"
BR-08: When 审核通过 Then 状态→"已发布"
→ SM: 草稿→[>5000]→待审核→[通过]→已发布→[到期]→已结束
```

**BR/SM 交织涌现**：整理 BR 时状态转换类规则自然聚合出 SM，不是线性推导。

聚合结果落到 MRD 时，物理位置与父链编号按 SKILL.md「MRD 文档大纲与编号规则」执行：SM 挂在所属 JF 下，权威定义收口于该 SM 的主导 JF；BR 随 UC-JF 归属分散，编号保持 BR-NN 全局连续。
