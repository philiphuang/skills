# shaping 8 件套契约

> jf-interview 产物的**唯一权威定义**。逐文件模板、字段要求、门禁 G1–G7 判定细则。
> 校验实现：`products/jiaofu/jf-interview/scripts/check_shaping.py`（以它为准，文档与脚本不一致时修文档）。

8 件套是访谈的**产物契约**：不管访谈由本 skill、外部 skill 还是人主持，
移交 jf-prd 前都必须交齐这 8 个文件并通过 G1–G7。
`shaping/` 默认与上游 MRD 同级（如 `docs/shaping/`）。

| 文件 | 内容 | 一句话定位 |
|---|---|---|
| `00-intake.md` | 原始输入与来源 | 一句话问题 + 上游 MRD 路径 |
| `01-problem.md` | 问题定义 | 谁、什么场景、现在怎么解决、为什么不够 |
| `02-users.md` | 目标用户与角色 | 对齐 MRD 的 BRO |
| `03-journey.md` | 用户旅程 | 主路径 + 分支，分支写明「用户看到什么」 |
| `04-scope.md` | MVP 边界 | 做/暂缓/不做/待确认 四分类 |
| `05-flows.md` | 关键流程 | 对齐 MRD 的 CP，补分支与异常 |
| `06-shaped-brief.md` | 定型摘要 | 1 页，可给客户看 |
| `07-open-questions.md` | 待确认清单 | 影响页面/拍板人/阻塞项 |

## 逐文件模板

### 00-intake.md

```markdown
# 原始输入与来源

一句话问题：<用户最初的那句话>
上游 MRD：<路径>（含 N 条 DR 待拍板：D-01 ~ D-NN）
输入来源：<访谈/纪要/邮件/代码，附时间点>
```

要点：来源逐条列出处与时间点；这是「能查文档的不许问人」的证据基线。

### 01-problem.md

```markdown
# 问题定义

<产品定位：1–2 句，谁在什么场景下需要什么、为什么现在的解法不够>

## 谁在什么场景
...

## 现在怎么解决
...

## 为什么不够
...
```

**G2 判定**：首段 = 第一个非空、非标题、非列表/表格/代码的段落。
**引用块（`>`）算正文**——`>` 剥掉后就是首段本身，不会滑到下一段去校验。
句数按 `。！？!?` 切分，须 ≥1 且 ≤3（超过 3 句打回）；推荐 2 句。

> 背景：早先把 `>` 当标记跳过，定位写成引用块时门禁校验的其实是**下一段**——
> 回测里报出来的句子来自「现在怎么解决」，看着像报了错，实际校验错了对象。

### 02-users.md

```markdown
# 目标用户与角色

对齐上游 MRD 的 BRO：

| 角色 | 是谁 | 用本系统做什么 | 关键诉求 |
|---|---|---|---|
| 预审员 | ... | ... | ... |
```

要点：角色与 MRD 的 BRO 一致；不同角色的**权限差异**（谁能看/谁能改/无权限隐藏还是禁用）
在这里盘清，追问维度「权限」落点在此。
若此处出现「口径冲突/口径不一致」字样，必须同步登记到 `07-open-questions.md`（G6）。

### 03-journey.md

```markdown
# 用户旅程

## 主路径
1. 步骤 → 步骤 → 步骤（对齐 MRD 的 JF）

## 分支
- **分支：<名称>**：触发：<条件>
  - 用户看到：<具体页面/内容/状态>
  - 后续：<去向，能否返回>
```

**G4 判定**：

- **条目块** = 顶层列表项 + 其缩进续行（与 `07` 的条目块定义一致）。顶层列表项认
  `- ` / `* ` / `+ ` **和有序列表** `1. ` / `1、` / `1)` / `1）`——中文文档里
  有序列表比 `-` 更常见，只认 `-` 会让整篇的分类/分支无人校验
- 凡含 **`分支：`**（冒号不可省，避免主路径里「两条候选分支见下」这种提及被误判）
  的条目块，必须同时含「用户看到什么」的任一写法：
  `看到` / `显示` / `展示` / `呈现` / `出现` / `弹出` / `跳转到`
- 写了 `分支：` 却**没写成条目块**（`### 分支：…` 小标题、行首加粗）→ 打回。
  门禁看不见它，等于这个分支「用户看到什么」根本没人校验——静默跳过是回测里
  最大的一个漏，比误报危险得多
- 任何非标题行不得出现「待定」——要么写清楚，要么进 `07-open-questions.md`
- 一条分支都没有会被 WARN（旅程无分支通常意味着没盘到位）

> 取舍说明：这里选**扩同义词表**而不是把判据降级为 WARN。该条要检查的是语义
> （「分支有没有写清用户看到什么」），单认「看到」只是实现上的偷懒写法，会把
> 「显示 XX 提示」「呈现错误页」这类正确描写误判为 ERROR。降级为 WARN 则会让
> G4 失去门禁效力——分支无从感知是下游 jf-ia/jf-validate 返工的主要来源，
> 值得继续硬拦。同义词放宽后仍保留反向用例（一个同义词都没有照样打回）。

### 04-scope.md

```markdown
# MVP 边界

## 做
- <逐项点名，可带页面 id>

## 暂缓
- <进 V2 的，写明触发条件>

## 不做
- <明确排除的，写明为什么>

## 待确认
- OQ-01｜<问题一句话>（拍板人：<谁>；影响面：<页面 id 或模块>）
```

**G3 判定**：

- 四分类标题（`##`–`####` 级，标题文本恰为分类词，**可带「项/事项/清单/列表/内容」后缀**，
  可带括号注释）各至少 1 条列表项
- 「待确认」每条（含其缩进子行）须同时含「拍板人」与「影响面」
- 分类逐项**点名**，不写「其余功能」这类打包话术

**G7 判定**（与 07 对账）：`04-scope.md` 的「待确认」与 `07-open-questions.md` 是
同一份清单的两个视图（前者写影响面，后者写拍板人与阻塞项），编号必须**一一对应**：

- 「待确认」每条须以 `OQ-<数字>｜` 开头（编号沿用 07 的，不重新编号）
- 两边编号集合必须相等：scope 有而 07 没有 → 打回；07 有而 scope 没有 → 打回
- 两边各自不得有重复编号

`冲突-NN` 条目不参与该集合比对（它对应的是被顶到用户面前的两次口径，
与 scope 的待确认不是同一类）。

> 背景：两处各自都校验过，却从来不比对。回测注入：07 从 8 条砍到 1 条，
> 门禁全绿——scope 里悬着的 7 条待确认就这么静悄悄地没了。

### 05-flows.md

```markdown
# 关键流程

对齐 MRD 的 CP，逐条补充分支与异常：

## <流程名>
主链：<步骤 → 步骤>
异常：<网络中断/会话过期/并发编辑/外部系统挂了时的行为>
```

要点：追问维度「边界与错误态」「集成依赖」的落点在此；外部依赖逐个写明
「它挂了怎么办、数据从哪来、多久同步一次」。

### 06-shaped-brief.md

1 页定型摘要，可给客户看：定位（同 01 首段）、用户与主旅程、MVP 边界、
关键待确认（同 07 的编号引用）。内容全部引用自 00–05 与 07，**不引入新决策**。

### 07-open-questions.md

```markdown
# 待确认清单

- OQ-01｜<问题一句话>｜DR: D-01｜影响页面: task-list（哪一部分受影响）｜拍板人: <谁>｜阻塞: <什么决策>
- 冲突-01｜<两次口径不一致的问题>｜影响页面: leader-review-list｜拍板人: <谁>｜阻塞: <什么>
  - 原话A：「……」——来源：<谁/哪份文档>，2026-08-30
  - 原话B：「……」——来源：<谁/哪份文档>，2026-09-05
  - 处置：<并列上抛，不自行裁决>
```

**G5 判定**：每个条目（以 `OQ-` 或 `冲突` 开头的顶层列表项，含其缩进子行）
必须含**页面 id**（小写字母+数字+连字符、至少一个连字符，如 `leader-review-list`，
与 jf-ia 产出的 manifest 页面 id 对齐）或 **MRD 的 DR 编号**（`DR: D-01` / `D-01` / `DR-1`）。

页面 id 的判定分四档：

| 情形 | 判据 | 结果 |
|---|---|---|
| 给了 `--manifest <manifest.json>` | 条目里的 kebab-case 词必须存在于 `manifest.pages[].id` | 有对不上的 → **ERROR**（打回） |
| 给了 `--manifest`，条目写了「影响页面」但里面取不到可识别的页面 id（写「见 DR 说明」、写中文页面名等） | 给了 manifest 就是要做页面级交叉校验 | **ERROR**（打回） |
| 给了 `--manifest`，条目压根没写「影响页面」字段 | 同上 | **ERROR**（打回） |
| 未给 `--manifest` | 排除内置的文档名/skill 名（`open-questions`、`check-shaping`、`jf-prd`、`shaping-contract`、任一 `jf-*` skill 名等） | 排除项不计入追溯依据；若条目的页面证据只剩排除项 → **WARN**（不静默通过） |

> 取舍说明：`--manifest` 下的「只靠 DR 编号追溯」早先只给 WARN，等于**把这项校验
> 关掉还照样放行**——门禁的可信度取决于最弱的那条路径。给了 manifest 就是要做
> 页面级交叉校验，取不到页面 id 一律打回；不给 manifest 时才退回 DR 编号兜底。

```bash
# 与 jf-ia 的 manifest 交叉校验
# 触发时机：manifest 已存在时——二次迭代，或 jf-ia 产出后回跑
# （首次移交 jf-prd 时 manifest 尚未产出，加这个参数会因读不到文件直接退出）
python3 products/jiaofu/jf-interview/scripts/check_shaping.py <shaping目录> \
    --manifest <仓库>/manifest.json
```

> 背景：`PAGE_ID_RE` 本身匹配任意 kebab-case 英文词，早先把 `task-list` 换成
> `open-questions`、`leader-review-list` 换成 `jf-prd` 也能 0 error 通过——门禁可被
> 廉价满足。现在这类写法要么被 `--manifest` 直接拒掉，要么在不给 manifest 时给 WARN。

**G6 判定**：

- 冲突条目须有 ≥2 条「原话」子行，且每条带「来源」与时间点（`年-月-日` / `年/月/日` / `X年X月X日`）
- `00`–`06` 任何文件出现疑似「两次口径」，而 07 一条冲突条目都没有 → 打回
- 冲突**只登记不裁决**；拍板后把处置结果写回条目（保留原话，历史可追溯）

疑似「两次口径」按 `。；！？` 与换行**逐句**判定，命中任一即算：

| # | 判据 | 例 |
|---|---|---|
| 1 | 含 `口径冲突` / `两次口径` / `口径不一致` | 「本环节口径冲突」 |
| 2 | 两次口径信号（`两次`/`前后`/`先前`/`原本`/`原来`/`起初`/`之前`/`后又`/`又改`/`改口`/`口径变`/`反口`，或「原先…现在…」句式，或同句 ≥2 个日期）**且** 强冲突词（`冲突`/`矛盾`/`不一致`/`对不上`/`相左`/`有出入`/`改了`/`变了`/`改成`/`改为`/`变更为`/`调整为`） | 「260811 的说法与 260814 的说法对不上」 |
| 3 | 两次口径信号 **且** 弱冲突词（`不同`/`不一样`）**且** 口径主语（`口径`/`说法`/`表述`/`要求`/`答复`/`定义`/`描述`/`结论`） | 「领导环节的要求前后不同」 |

> 取舍说明：**宁可多报也不漏报**。G6 要抓的是「同一件事有两次不同口径」，
> 而中文里有无穷种写法——早先只认三个词，回测里「260811 与 260814 的说法对不上」
> 这种最自然的写法直接全绿通过，冲突就这么被 agent 自行裁决掉了。
>
> 已知的两处代价：① 把「需求改了」这类正常表述也报出来；
> ② 07 只要有**任何一条**冲突条目，`01`–`06` 的疑似字样就不再逐条比对
> （避免同一条冲突在多处复述时反复报错），因此「07 只登记了其中一条」的情形会放过。
> ② 是当前判据的粗处，但它要的是语义级配对，不属可机检范围——靠 07 的冲突条目
> 模板（原话 + 来源 + 时间点）在人读那一步兜住。

## 待确认条目字段（三件套）

| 字段 | 含义 | 例 |
|---|---|---|
| 影响页面 | 哪些页面 id 或 DR 编号被这条卡住 | `leader-review-list、leader-review-detail` |
| 拍板人 | 谁能拍板（角色，不写人名） | 甲方分管领导 |
| 阻塞项 | 不拍板就动不了的决策 | 页面清单增减、导航归属 |

未拍板条目进 jf-prd/jf-ia 后，按影响页面落到 manifest 的 `pages[].note`
（落法见 `products/jiaofu/jf-contract/references/manifest-schema.md`）。

## 门禁 G1–G7 汇总

| # | 条件 | 判定实现 |
|---|---|---|
| G1 | 8 件套全部存在且非空 | 8 个文件在目录中且 strip 后非空 |
| G2 | 定位可 1–2 句表达 | `01-problem.md` 首段句数 1–3（按 `。！？!?` 切分）；引用块算正文 |
| G3 | 四分类每项 ≥1 条，待确认有责任人与影响面 | `04-scope.md` 四标题（可带「项/事项/…」后缀）各 ≥1 列表项；待确认条目含「拍板人」「影响面」 |
| G4 | 分支写明「用户看到什么」 | 含 `分支：` 的条目块（含子行，有序列表也算条目）必含 `看到`/`显示`/`展示`/`呈现`/`出现`/`弹出`/`跳转到` 之一；写了 `分支：` 却不成条目块 → 打回；任何非标题行不得含「待定」 |
| G5 | 每条可追溯 | 07 条目含页面 id 或 DR 编号；给了 `--manifest` 时页面 id 必须存在于 `manifest.pages[]` 且**必须有**页面 id；未给时排除文档名/skill 名并对排除项给 WARN |
| G6 | 冲突单列不裁决 | 冲突条目 ≥2 原话（带来源+时间）；01–06 的疑似「两次口径」字样必须对应 07 冲突条目 |
| G7 | 待确认两处对账 | `04-scope.md` 与 `07-open-questions.md` 的 OQ 编号集合相等、各自不重复；scope 每条带 OQ 编号 |

WARN（不算失败，但要看）：`03-journey.md` 无分支条目；07 条目缺「拍板人/阻塞」字段；
`00-intake.md` 未提及上游 MRD；07 条目的页面 id 疑似写成了文档名/skill 名（G5，未给
`--manifest` 时的兜底）。

> 回测（2026-09，拿「51、专利省内预审」真实产物注入 18 类作者常见的错）之后的加固：
> H1 有序列表分支不被识别、H2 冲突用自然说法认不出、H3 定位写引用块时校验错段落、
> H4 `--manifest` 下缺页面 id 只警告、H5 scope 与 07 编号从不对账，
> 外加一个误报（`## 待确认项` 匹配不上）。回归用例见
> `tests/unit/scripts/test_check_shaping.py`。
